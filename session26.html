Introduction to REST API

An API (Application Programming Interface) allows different applications to communicate with each other.

Instead of returning HTML pages, a REST API returns data in JSON format.

Key Difference

A Django Website returns HTML, whereas a REST API returns JSON that can be consumed by Mobile Apps, React, Angular and other applications.

Why do we need REST APIs?
  • Share data with Mobile Applications.
  • Connect Django with React or Angular.
  • Exchange data using JSON.
  • Allow different applications to communicate with the same database.
  • Reuse the same Backend for multiple Frontend applications.

Install Django REST Framework

Django REST Framework (DRF) is the most popular library for building REST APIs in Django.

Step 1 - Install Package

Step 3 - Verify Installation
python manage.py runserver

If the server starts without any errors, Django REST Framework has been installed successfully.

Result The project is now ready to create REST APIs using Django REST Framework.

Create Serializer

A Serializer converts Django Model objects into JSON format and vice versa.

It acts as a bridge between the Django Model and the REST API.

Step 1 - Create serializers.py
blog/serializers.py
Step 2 - Create CategorySerializer
from rest_framework import serializers

from .models import Category


class CategorySerializer(serializers.ModelSerializer):

    class Meta:

        model = Category

        fields = "__all__"
Understanding ModelSerializer
Concept Purpose
ModelSerializer Automatically creates serializer fields from a Django Model.
model Specifies which Model will be serialized.
fields="__all__" Includes all fields of the Model in the JSON response.

Organize REST API Files

As the project grows, it is a good practice to separate Website Views and REST API Views.

Instead of placing all API methods inside views.py, we will create a separate api_views.py file.

Step 1 - Create api_views.py
blog/api_views.py
Step 2 - Create api_urls.py
blog/api_urls.py
Step 3 - Register API URLs
from django.urls import path, include


urlpatterns = [

    path("", include("blog.urls")),

    path("api/", include("blog.api_urls")),

]
Step 4 - Project Structure
blog/

│

├── admin.py

├── models.py

├── forms.py

├── serializers.py

├── views.py          (Website Views)

├── api_views.py      (REST API Views)

├── urls.py           (Website URLs)

├── api_urls.py       (REST API URLs)

├── templates/

└── static/
Result The project is now organized with separate files for Website and REST API development.
Why do we create api_views.py?
Website REST API
views.py api_views.py
Returns HTML Pages Returns JSON Data
Uses render() Uses Response()
Accessed by Browser Accessed by Mobile Apps, React, Angular, etc.

Separating Website Views and API Views keeps the project clean, organized and easier to maintain as the application grows.

Build Category REST APIs

In this section, we will build complete CRUD APIs for the Category model using Django REST Framework.

Step 1 - Update api_views.py
from rest_framework.decorators import api_view

from rest_framework.response import Response

from rest_framework import status

from .models import Category

from .serializers import CategorySerializer
Step 2 - GET All Categories
@api_view(["GET"])

def category_list(request):

    categories = Category.objects.all()

    serializer = CategorySerializer(

        categories,

        many=True

    )

    return Response(serializer.data)
Step 3 - GET Category by Id
@api_view(["GET"])

def category_detail(request, id):

    category = Category.objects.get(Id=id)

    serializer = CategorySerializer(category)

    return Response(serializer.data)
Step 4 - Update api_urls.py
from django.urls import path

from . import api_views


urlpatterns = [

    path(

        "categories/",

        api_views.category_list

    ),

    path(

        "categories/<int:id>/",

        api_views.category_detail

    ),

]
Note

After creating api_urls.py, it must be registered in the project's main urls.py. Otherwise, Django will not recognize the API routes. 

from django.urls import path, include

urlpatterns = [

    path("", include("blog.urls")),

    path("api/", include("blog.api_urls")),

]

Now all API URLs will be available under the /api/ prefix.

New Concepts Used
Concept Purpose
@api_view(["GET"]) Allows the View to handle GET requests.
many=True Serializes multiple records.
serializer.data Converts Model objects into JSON.
Response() Returns a JSON response instead of an HTML page.

Create, Update and Delete Category APIs

Now we will create REST APIs to insert, update and delete Category records using HTTP requests.

Step 1 - POST API (Create Category)
@api_view(["POST"])

def category_create(request):

    serializer = CategorySerializer(

        data=request.data

    )

    if serializer.is_valid():

        serializer.save()

        return Response(

            serializer.data,

            status=status.HTTP_201_CREATED

        )

    return Response(

        serializer.errors,

        status=status.HTTP_400_BAD_REQUEST

    )
Step 2 - PUT API (Update Category)
@api_view(["PUT"])

def category_update(request, id):

    category = Category.objects.get(Id=id)

    serializer = CategorySerializer(

        category,

        data=request.data

    )

    if serializer.is_valid():

        serializer.save()

        return Response(serializer.data)

    return Response(

        serializer.errors,

        status=status.HTTP_400_BAD_REQUEST

    )
Step 3 - DELETE API
@api_view(["DELETE"])

def category_delete(request, id):

    category = Category.objects.get(Id=id)

    category.delete()

    return Response(

        {

            "message":

            "Category Deleted Successfully."

        },

        status=status.HTTP_200_OK

    )
Step 4 - Update api_urls.py
path(

    "categories/create/",

    api_views.category_create

),

path(

    "categories/update/<int:id>/",

    api_views.category_update

),

path(

    "categories/delete/<int:id>/",

    api_views.category_delete

),
Result The Category module now supports complete CRUD operations using REST APIs.
